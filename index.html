01

화면 3곳, 일 4단계

00:04 · 6분

Antigravity는 내 PC 폴더의 파일을 직접 읽고, 정리하고, 새 파일로 저장해 주는 비서입니다. 웹 채팅처럼 파일을 하나씩 올릴 필요가 없습니다. 폴더를 열어 두고 말로 맡기면 됩니다.

화면은 3곳만 보면 됩니다

개념도입니다. 실제 화면 배치와 메뉴 이름은 앱 버전에 따라 조금 다릅니다.

일은 4단계로 맡깁니다

1. 맡기기

어떤 파일을, 무엇을 해서, 어떤 형태로 남길지 한 번에 말합니다.

2. 계획 보기 (필요할 때만)

큰 일은 /plan으로 계획을 먼저 받아 고칩니다. 작은 일은 생략합니다.

3. 실행 지켜보기

파일을 읽고 만드는 과정이 가운데에 보입니다. 허락을 묻는 창이 뜨면 읽고 결정합니다.

4. 결과 검토

오른쪽 결과를 원문과 대조합니다. 고칠 점은 "2번째 줄 기한 다시 계산해 줘"처럼 짚어서 말합니다.

잘 맡기는 문장 = 자료 + 할 일 + 결과 형태 + 주의할 점

요소나쁜 예좋은 예
자료사건 자료 보고01_기일메모 폴더의 메모 3개만 읽고
할 일정리해 줘사건별 할 일과 기한을 뽑고 항소·상고 기한을 계산해서
결과 형태(없음)표 하나로 01_기일표.md에 저장해 줘
주의할 점(없음)확실하지 않으면 "확인 필요"라고 적어 줘
02

기다리지 않게 쓰는 법

00:10 · 6분

Antigravity가 오래 걸리는 이유는 대부분 너무 많이 읽거나, 너무 깊게 생각하거나, 사람의 허락을 기다리기 때문입니다. 아래 5가지만 바꿔도 체감 시간이 크게 줄어듭니다.

#오래 걸리는 원인이렇게 바꿉니다어디서
1단순한 일에 가장 무거운 모델·높은 추론 수준표 정리·대조·메일 초안은 Flash + Low. 판례 비교처럼 따져야 할 일만 Medium 이상입력창 아래 모델 선택
2폴더 전체를 훑어봄"이 폴더(파일)만 읽고, 다른 폴더는 보지 마"라고 범위를 적습니다. 결과 파일 이름도 정해 줍니다지시문
3작은 일에도 계획서를 만들고 승인을 기다림작은 일은 "계획 없이 바로 해 줘". 계획 검토는 설정의 Plan Review Policy에서 "에이전트가 판단"으로 둘 수 있습니다지시문 · 설정
4허락 창이 떠 있는데 다른 일을 하느라 못 봄설정 > Notifications에서 알림 소리를 켭니다. 허락 창은 입력창 위에 뜹니다설정
5결과를 화면 앞에서 기다림기다리는 동안 새 대화를 열어 다른 일을 맡기거나, 다음 지시를 미리 입력해 두면 차례로 실행됩니다. 매주 하는 정리는 Automations로 출근 전에 돌려 둡니다왼쪽 대화 목록

같은 일, 두 가지 지시문

느린 지시

사건 자료들 보고 기한 관련된 거 정리 좀 해 줘.

→ 폴더 전체를 읽고, 무엇을 만들지 계획부터 세우고, 결과 형태를 다시 물어봅니다.

빠른 지시

01_기일메모 폴더의 메모 3개만 읽고, 사건·할 일·기한·근거 4칸 표로 01_기일표.md에 저장해 줘. 계획 없이 바로 해 줘.

→ 파일 3개만 읽고 바로 표를 씁니다.

이것도 알아 두세요
  • 대화가 길어져 느려지면 /compact로 지금까지의 대화를 요약해 가볍게 합니다.
  • 진행 중에 궁금한 것은 /btw로 옆에서 따로 묻습니다. 하던 일은 멈추지 않습니다.
  • 반대로 큰 일은 처음에 몇 분을 들여 /grill-me·/plan으로 방향을 맞추는 편이 다시 시키는 시간보다 짧습니다. 실습 5에서 해 봅니다.
  • 같은 설명을 매번 쓰고 있다면 3장 실습 4처럼 스킬로 저장해 둡니다. 다음부터는 설명이 짧아집니다.

실습 1. 기일·기한표 만들기

8분01_기일메모

사건 메모 3개에서 할 일과 기한을 뽑아 한 장의 표로 만듭니다. 항소·상고 기한 계산도 맡겨 보고, AI 계산을 그대로 믿으면 안 되는 이유를 확인합니다.

01_기일메모 폴더의 메모 3개만 읽어 줘. 다른 폴더는 보지 마. 사건별로 "사건 | 할 일 | 기한 | 근거 | 확인" 5칸 표 하나로 정리해서 01_기일표.md로 저장해 줘. - 항소·상고 기한은 판결정본 송달일 기준 민사소송법으로 계산하고, 첫날은 빼고 세. 말일이 토요일이나 공휴일이면 다음 날로 넘겨. - 계산 근거(조문, 날짜 계산)를 근거 칸에 한 줄로 적어. - 메모에 없는 내용은 만들지 말고, 확실하지 않으면 확인 칸에 "변호사 확인 필요"라고 적어. 계획 없이 바로 해 줘.

결과에서 확인할 것

  • 사건 A 항소 기한이 2026. 11. 3.(화)인지 (10. 20. 송달 + 2주)
  • 사건 C는 토요일(10. 24.)에 송달됐습니다. 2주 뒤 말일이 11. 7.(토), 다음 날 11. 8.(일)도 공휴일이라 11. 9.(월)에 만료되는지
  • 사건 B의 내부 기한(11. 5.)과 법원 기한(11. 12.)을 구분했는지
꼭 기억하세요기한 계산은 AI가 틀리기 쉬운 대표 업무입니다. 표는 "초안"이고, 송달 기록과 조문으로 사람이 마지막 확인을 합니다. 틀린 줄이 있으면 "C 사건 기한을 민법 제161조 기준으로 다시 계산해 줘"처럼 줄을 짚어 고치게 하세요.

실습 2. 준비서면과 증거목록 대조

8분02_서면대조

서면에 인용한 호증 번호·증거명·날짜가 증거목록과 맞는지 하나하나 대조합니다. 사람이 하면 30분 넘게 걸리는 일입니다. 초안에는 일부러 틀린 곳을 넣어 두었습니다.

02_서면대조 폴더의 준비서면_초안.md와 증거목록.csv만 읽어 줘. 서면에 나오는 호증(갑 제○호증)을 모두 찾아서 증거목록과 대조해 줘. - 호증 번호, 증거명, 날짜가 서로 다르거나, 목록에 없는 호증을 인용했거나, 서면 속 기간 표현(예: "3일 이내")이 증거 날짜와 맞지 않으면 모두 찾아. - 결과는 "번호 | 서면 위치 | 서면 내용 | 증거목록 | 판단" 표로 02_대조결과.md에 저장해 줘. - 서면 파일은 고치지 마. 계획 없이 바로 해 줘.

결과에서 확인할 것 (심어 둔 오류 4개)

  1. 계약 체결일: 서면 2025. 3. 15. ↔ 갑 제1호증 작성일 2025-03-05
  2. 갑 제4호증: 서면은 "기성청구서", 목록은 "세금계산서"
  3. 갑 제7호증(현장 회의록): 목록에 없음 (갑 제6호증까지)
  4. "3일 이내 공기 연장 요청": 공문 8. 15. → 요청서 8. 21.이므로 6일
한 걸음 더"서면 파일은 고치지 마"라고 쓴 이유는 원본 보호입니다. 고친 버전이 필요하면 "준비서면_수정안.md로 새 파일에 고쳐 줘"처럼 새 파일로 받으세요.

실습 3. 판결 3건 비교표와 시사점

8분03_판결비교

여러 판결을 같은 기준으로 나란히 놓는 일입니다. 비교 기준을 내가 정해 주는 것이 핵심입니다. 이 실습만 추론 수준을 Medium으로 올립니다.

03_판결비교 폴더의 판결요지 3개와 05_GE_실습/사건A_쟁점정리_메모.md만 읽어 줘. 1) 판결 3건을 "선고일 | 쟁점 | 공기 연장 인정 여부 | 지체상금 감액 비율 | 결과" 기준 표로 비교해 줘. 2) 그 아래에 사건 A에 주는 시사점을 3줄 이내로 적어 줘. 판결 요지에 없는 내용은 쓰지 말고, 각 줄 끝에 근거 판결 번호를 붙여. 03_판결비교표.md로 저장해 줘. 계획 없이 바로 해 줘.

결과에서 확인할 것

  • 감액 비율: 판결 1은 50%, 판결 2는 30%, 판결 3은 감액 배척
  • 시사점이 "사건 A는 6일 뒤 요청(계약상 7일) → 판결 1과 가까움", "인과관계 증명(회의록)이 중요"로 요약되는지
  • 각 줄에 근거 판결 번호가 붙었는지. 근거 없는 문장은 지우게 합니다
실제 업무에서는여기 판결은 모두 가상입니다. 실제 판례를 인용할 때는 AI가 적은 사건번호·선고일·판시사항을 반드시 판례 원문에서 확인하세요. 존재하지 않는 판례를 그럴듯하게 만들어 내는 경우가 있습니다.

실습 4. 의뢰인 보고 메일 + 스킬로 저장

6분04_보고메일

기일 결과 메모로 의뢰인 보고 메일 초안을 쓰고, 세종의 작성 규칙을 스킬로 저장합니다. 스킬은 "이럴 때는 이렇게 하라"는 업무 설명서입니다. 한 번 만들어 두면 다음부터 규칙을 다시 설명하지 않아도 됩니다.

① 메일 초안 받기

04_보고메일 폴더의 기일결과_메모.md와 세종_보고메일_작성규칙.md만 읽어 줘. 작성 규칙대로 의뢰인(서진테크 법무팀)에게 보낼 기일 결과 보고 메일 초안을 04_보고메일_초안.md로 저장해 줘. 메모에 없는 날짜나 요청 사항은 만들지 말고 [확인 필요]로 비워 둬. 계획 없이 바로 해 줘.

② 같은 규칙을 스킬로 저장하기

방금 쓴 작성 규칙을 이 프로젝트의 스킬로 만들어 줘. 스킬 이름은 sejong-client-report, 설명은 "의뢰인에게 기일·진행 결과를 보고하는 메일을 쓸 때 사용"으로 해 줘. .agents/skills/sejong-client-report/SKILL.md 에 저장해 줘.

다음부터는 입력창에 /sejong-client-report를 입력하거나, "보고 메일 써 줘"라고만 해도 이 규칙을 따릅니다.

스킬은 어디에 저장되나요?프로젝트 폴더/.agents/skills/에 두면 이 폴더에서만, ~/.gemini/config/skills/에 두면 내 PC의 모든 프로젝트에서 씁니다. 팀이 같은 규칙을 쓰려면 프로젝트 폴더째 공유합니다.

실습 5. 큰 일 맡기기 — /grill-me → /plan → /goal

9분02 · 03 · 05 폴더

실습 1~4는 "무엇을 만들지" 내가 정확히 알고 있는 작은 일이었습니다. 이번에는 사건 A 항소 검토 자료 묶음처럼 여러 단계가 있고 요구사항이 아직 흐릿한 큰 일을 맡깁니다. 입력창에 /를 치면 명령 목록이 나옵니다.

명령하는 일이럴 때 씁니다
/grill-me일을 시작하기 전에 한 번에 하나씩 질문합니다. 질문마다 추천 답이 맨 위에 붙어 있어 고르기만 하면 됩니다.내가 원하는 결과를 아직 말로 정리하지 못했을 때
/plan파일을 고치지 않고 자료만 살펴본 뒤 계획서를 씁니다. 계획에 의견을 달고 Proceed를 눌러야 실행합니다.단계가 여러 개이거나, 실행 전에 순서·범위를 확인하고 싶을 때
/goal완료 기준을 채울 때까지 중간에 멈추지 않고 계속 일합니다. 끝내기 전에 기준을 하나씩 스스로 점검합니다.할 일이 정해졌고, 맡겨 두고 다른 일을 하고 싶을 때

5-1. /grill-me — 질문에 답하며 요구사항 정하기 (3분)

/grill-me 사건 A(한빛물산) 항소 여부를 의뢰인에게 설명할 항소 검토 자료를 만들고 싶어. 자료는 01_기일메모, 02_서면대조, 03_판결비교, 05_GE_실습 폴더만 써. 질문이 끝나면 정한 내용을 5줄로 요약만 하고, 파일은 아직 만들지 마.

에이전트가 예를 들어 이런 질문을 합니다. 추천 답이 맞으면 그대로 고르고, 아니면 Other에 직접 적은 뒤 Submit을 누릅니다. 넘어가려면 Skip입니다.

  • 누가 읽나요? → (추천) 의뢰인 법무팀
  • 결과물은 몇 개로 나눌까요? → (추천) 보고서, 증거 보완 목록, 일정표 3개
  • 판결은 어디까지 인용할까요? → (추천) 폴더 안의 판결 요지만

질문 내용은 예시입니다. 실제 질문은 자료와 앞의 답에 따라 달라집니다.

5-2. /plan — 계획서 받고 고친 뒤 실행 (3분)

/plan 방금 정한 내용대로 사건 A 항소 검토 자료 3개(항소검토_보고서.md, 증거보완_목록.md, 일정표.md)를 05_항소검토 폴더에 만들어 줘. 기존 파일은 고치지 마.
  1. 오른쪽에 계획서(Implementation Plan)가 열립니다. 아직 파일은 바뀌지 않았습니다.
  2. 고칠 단계를 드래그해 의견을 답니다. 예: "외부 판례 검색 단계는 빼 줘. 폴더 안 자료만 써."
  3. 의견을 반영한 계획을 확인하고 Proceed를 누르면 실행합니다.
한 번에 하려면/plan /grill-me 할 일처럼 둘을 붙이면 질문에 답한 내용으로 바로 계획서를 씁니다.

5-3. /goal — 완료 기준을 주고 끝까지 맡기기 (3분, 강사 시연)

/goal은 완료 기준이 분명할수록 빨리 끝납니다. 기준이 흐리면 몇십 분 넘게 이어질 수 있어, 교육에서는 강사가 시작만 보여 주고 결과는 00_미리_만든_결과/05_항소검토로 봅니다.

/goal 아래 기준을 모두 채울 때까지 05_항소검토 폴더의 자료를 완성해 줘. 1. 항소검토_보고서.md, 증거보완_목록.md, 일정표.md 3개 파일이 모두 있다. 2. 보고서의 모든 문단 끝에 [근거: 파일 이름]이 붙어 있다. 3. 항소장 제출 기한이 세 파일 모두 2026. 11. 3.(화)로 같다. 4. 폴더 자료에 없는 사실은 쓰지 않았고, 확실하지 않은 것은 "변호사 확인 필요"로 표시했다. 범위: 01·02·03·05 폴더만 읽고, 05_항소검토 폴더에만 쓴다. 다른 파일은 고치지 않는다.
  • 완료 기준은 눈으로 확인할 수 있게 씁니다. "파일 3개가 있다", "모든 문단에 근거가 붙어 있다"처럼요.
  • 범위(읽을 폴더, 쓸 폴더)를 함께 적어야 일이 끝없이 커지지 않습니다.
  • 중간에 멈추려면 "멈춰"라고 보내면 됩니다. 새 /goal을 시작해도 이전 목표는 취소됩니다.
  • /goal이어도 권한 설정은 그대로라 허락 창은 뜰 수 있습니다. 알림 소리를 켜 두세요.

6-1. 프로젝트에 사건 자료 올려 두고 질문하기

6분 · 실습

GE의 프로젝트는 파일을 올려 두고 그 파일을 근거로 대화하는 개인 작업 공간입니다. 사건마다 하나씩 만들어 두면 매번 파일을 다시 올리지 않아도 됩니다.

  2. 03_판결비교의 판결요지 3개와 05_GE_실습/사건A_쟁점정리_메모.md를 올립니다.
  3. 아래 질문을 넣고, 답에 붙은 출처 파일을 눌러 원문과 맞는지 확인합니다.
올린 파일만 근거로 답해 줘. 사건 A에서 공기 연장 요청 기한을 지킨 것이 지체일수 계산에 어떤 영향을 줄 수 있는지, 판결 3건 중 어느 판결과 사실관계가 가장 가까운지 설명해 줘. 문장마다 근거 파일 이름을 붙이고, 파일에 없는 내용은 "자료에 없음"이라고 적어 줘.

6-2. Deep Research로 쟁점 조사

5분 · 강사 시연

Deep Research는 여러 웹 자료를 찾아 읽고 출처가 붙은 보고서를 만듭니다. 몇 분 이상 걸리므로 교육에서는 시작하는 법만 보고, 결과는 강사가 미리 받아 둔 보고서로 봅니다.

건설 하도급 공사에서 도급인의 설계 변경으로 공사가 지연된 경우, 수급인의 공기 연장 요청과 지체상금 감액에 관한 대한민국 대법원 판례 경향을 조사해 줘. 1) 공기 연장 요청 기한을 지켰는지가 지체일수 산정에 미친 영향 2) 설계 변경과 지연 사이의 인과관계 증명 방법(공정표·회의록 등) 3) 지체상금 감액 비율을 정한 기준 각 판례는 사건번호와 선고일을 적고, 확인할 수 있는 출처 링크를 붙여 줘.
확인 습관보고서의 사건번호·선고일·판시사항은 대법원 종합법률정보 등 판례 원문에서 하나씩 확인합니다. 링크가 없는 판례는 쓰지 않습니다.

6-3. Canvas로 의뢰인 보고서 다듬고 Word로 받기

6분 · 실습

Antigravity에서 만든 메일 초안(실습 4 결과)을 GE Canvas로 옮겨 문장을 다듬고 Word 파일로 내보냅니다.

  1. 00_미리_만든_결과/04_보고메일_결과.md(또는 내 실습 4 결과)를 올리고 아래 지시를 넣습니다.
  2. Canvas 편집 화면에서 고칠 문장을 직접 선택해 "더 정중하게"처럼 부분 수정을 요청합니다.
  3. 오른쪽 위 내보내기에서 Word(DOCX)로 받습니다.
올린 메일 초안을 Canvas에서 의뢰인 보고서 형식(A4 1쪽)으로 바꿔 줘. 제목, 결론 한 줄, 진행 결과, 앞으로의 일정(표), 귀사에서 하실 일 순서로 정리하고, 초안에 없는 사실은 추가하지 마.
